The plugin's interface inside the harness shell

This is a design of the interface: the tab's blocks are brought to one scheme — one number per block, no repeated counter, summary or name; empty groups are not printed at all, because the header counters already name them. The tokens are copied verbatim from the DSH design system, the elements and their order are the same as the client's; the typography and the class vocabulary are shared by all surfaces. Switch the theme with the button at the top right; disclosures and tool rows are clickable.

1. The sidebar tab — one surface

Contract: docs/design/contracts/single-surface.md. Body order: servers → sessions (only on a divergence) → tools → problems (only when there are any) → logs. One block scheme: an uppercase label on the left, the number on the right of the block's header, rows under it, a fact as a .detail line under its own row. An empty group is not drawn: the header counters already said "0".

A project's block is the same server rows as in the tab and the same one-line divergence section. The poll interval's row sits above the bar.

4. Differences and boundaries

WhatHereWhy
The block scheme and the copy brought to one scheme (this is a design) the product still prints the old strings: the session summary twice, the tool name both in the row and in its expansion, extra labels. The mock's fix runs ahead of the code fix — the divergence is closed in the next step, together with the src/client/view.ts fix. The zeroes are agreed: the header counters are chips, and an empty tier is drawn neither as a heading nor as a row (F-37)
The rows of the hidden tier (F-40) a disclosure heading ▸ hidden with a chip, under it the names as rows without a second level (tool-line static), like the pinned and counter ones the product draws the same tier as a disclosure and the same list, but makes a name row an expanding button with aria-expanded="false" and the hint "show this tool’s registry name and how it was offered", with nothing to expand (onToggle is a stub): a press does nothing while the hint promises an expansion. Awaiting the src/client/view.ts fix — an idea in docs/features.md
Tokens a verbatim copy of the three design-system sheets the page lives without a build and without the harness; names and values were not rewritten
Elements and order the same as the client's the bar, the blocks, the disclosures, the tool rows and the 12 px ladder — per contracts/surfaces.md
Toasts outside this interface design the section is removed as redundant; the banner's shape lives in src/client/toasts.ts and did not change
The shell (sidebar, chat, settings dialog) an approximation the shell classes are hashed by the build, the shell components are outside this repository; sizes and tokens are taken from their CSS (sidebar 451 px — the width at which the live panel was measured; dialog 800×min(800px,100vh−48px), rail 188)
--dsw-font-mono not declared there is no such variable in the design system (there are --dsw-font-family and --ds-font-family-code): the mono stack always resolves to the fallback — here and in the client alike
The panel's font inherits the shell's font (sans, 14 px) mono only on names, times and chips, as in the client
Text sizes relative em off the shell's type same as in the client: a label 0.8 em, a fact 0.85 em, a row the base size
Fixture data the /example/service project, 7 servers, 4 events matches the scripts/design-parity.mjs gate's fixture, so the mock and the machine checks speak about one thing
The server rows of the Tools page (F-44) the server name on the left, the transport and the server's toggle on the right the product keeps a Server label on the left with the offering phrase (1 of 3 tools offered directly) and puts the name on the right, next to the toggle (STYLE.settingRowControl, gap 6 px). A divergence in the stand's own layout, also recorded in docs/design/README.md §4
The tools filter bar (F-43) present in the full state: a query field, Clear, a note and four tier chips that really filter the list (a query by name, a tier on press, the hidden tier opens by itself) the tab's other states (quiet, mode-direct) are brief retellings of their cases and lag not only here: mode-direct prints the line "1 pinned · 0 disclosed · 0 hidden" in the tools block instead of the chips (pre-F-37). The numbers and the bar's shape — per contracts/surfaces.md §1.5
Call counters (F-32) absent from this file here the product ran ahead of the mock, not the other way around: a tool row prints {n} calls or never called, a quiet server — idle {n}d, and the pin picker sorts by frequency, all from the host's ProjectSnapshot.usage (src/types.ts:335-347), which the mock does not have. Porting it into the mock is a separate step of work
